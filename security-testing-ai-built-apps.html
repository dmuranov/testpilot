// security testing for ai-built apps

Can one user see another user's data in your app?

Security testing for AI-built apps means checking that User A cannot see or change User B's data. Apps made with tools like Lovable, Base44, Bolt, v0 or Bubble often work perfectly for the person who built them, and still leave doors open for everyone else. These are the checks that matter most, and how TestPilot runs them for you.

What goes wrong

AI tools build what you ask for. They rarely ask what should be forbidden. The result is an app where the right user sees the right page, and a wrong user may see it too.

  1. URL manipulation. Log in, open a record, and change the ID in the address. If another user's record opens, the app does not check who is asking.
  2. IDOR (insecure direct object reference). Same idea, deeper: the app trusts an ID sent by the browser. Test it on every page and action that takes an ID: invoices, profiles, orders, files.
  3. Role escalation. Log in as a regular user and try to reach admin pages or actions. A hidden button is not protection if the page still opens.
  4. Session persistence. Log out and press back. Open a private page in a new tab. A session that stays alive when it should not is a risk.

How TestPilot helps

TestPilot's security testing checks URL manipulation, IDOR, session persistence and role escalation, the kinds of problems no-code builders often miss. You describe what each user should and should not see, and TestPilot tries it with real accounts. With multi-role testing (beta), it can run scenarios across several users in one run: a dispatcher assigns a job, a contractor bids, an admin approves. The report logs every step with screenshots and flags problems by severity.

Questions

Is security testing different from normal testing?
Yes. Normal testing checks that things work. Security testing checks that the wrong person cannot make them work.

Do I need to know how to code?
No. You describe the scenario in plain English.

Does TestPilot store my app's data?
It stores only what your report needs: the learned page map and run screenshots, scoped to your account. Never sold or shared, and deletable.

Is it a full security audit?
No. TestPilot is not a full security audit or a penetration test. It tests the app the way a user could attack it from the browser. If you handle payments, health data or anything regulated, get a professional review as well.
