Test your Lovable app before your first real users do

Your Lovable app works in the editor. Real users click in a different order, submit half-filled forms and open pages you never checked. Testing a Lovable app before launch means using it the way a customer would, and writing down every place it breaks. Here is how to do it, by hand or with TestPilot.

  1. List the flows that matter. Write down what a user comes to do: sign up, log in, create a record, pay, send a message. Test those first. If they fail, nothing else matters.
  2. Test the unhappy paths. Leave fields empty. Type an invalid email. Go back mid-flow. Refresh a page. Open a page while logged out. Most bugs in AI-built apps are not in the happy path.
  3. Check every role. If your app has more than one kind of user (admin and customer, for example), log in as each and confirm each sees only what they should.
  4. Check security basics. Try changing the ID in a page address and see whether you can open another user's data. See the page on security testing for AI-built apps.
  5. Write down what you find. For each bug: the steps, what you expected, what happened, and a screenshot.
