How to test a Lovable app before launch

Lovable gets you from idea to working app fast. What it doesn't do is click through every screen the way your first customers will. This is the checklist to run before you share the link, and how to let TestPilot run it for you.

Why Lovable apps break after launch

Each prompt changes code you didn't write by hand. A fix to the dashboard can quietly break sign-up; a new table can come without the access rules the old ones had. The preview looks fine because you are logged in as yourself, with your own data. Real users arrive logged out, on a phone, with empty accounts and typos in their email.

The pre-launch checklist

  1. Sign-up and log-in from zero. New email, wrong password, password reset, log out and back in. Do it in a private window so no old session helps you.
  2. Your main flow, end to end. The one thing a customer comes for: create the booking, post the listing, send the invoice. Check that the result actually shows up where it should.
  3. Forms with bad input. Empty fields, very long text, a date in the past, a price of zero. Every form should say what's wrong instead of failing silently.
  4. Two users, two accounts. Log in as user A, copy a URL with an id in it, open it as user B. If B can see A's data, your Supabase row-level security needs work.
  5. Mobile. Most first visits come from a phone. Check menus, modals and buttons that end up off-screen.
  6. Empty states and errors. A brand-new account with no data, a slow network, a page refresh in the middle of a step.
